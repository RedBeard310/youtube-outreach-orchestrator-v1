The three questions

Q1Why is every discovery lane stopped right now?

The shared file that holds all 66 YouTube API keys was overwritten with an empty file at 04:58:11Z, and it is still empty. That file is ~/env-storage/.env, and it is the one place a key is ever added. Casey's Mac copies its own version over the server's every two minutes, and one of those copies wrote nothing.

Every process that started after that read no keys. You can watch it happen in the logs: sweeps up to 05:22Z print "66 direct keys", and every sweep from 05:36Z on prints "0 direct keys". There is no error in between. That line reads like a normal startup.

Then it got worse, because of what the pipeline does with no keys. It falls back to RapidAPI, which we retired on 08-10. Retired does not mean gone: the account has lapsed onto a free plan of 1,000 requests and 100 searches per day, and it answers normally. So the runs used it, spent about 950 of those 1,000 requests, and the meter that watches it wrote 95.2% used into a shared file.

Every discovery lane reads that file before it starts, and treats it as the YouTube quota. All five pause above 70%. So they paused, and stayed paused: eight straight runs of the main lane, once every fifteen minutes from 05:36Z to now, each one printing "PAUSE: quota at 95.1%" and quitting.

The number is about the wrong pool. It measures a backup service's free tier. The real pool, the 66 direct keys, resets at midnight Pacific and 65 of the 66 are alive at this moment. The pipeline stopped itself on a reading that had nothing to do with its own capacity.

Two fixes shipped, and neither can fix the empty file. The lanes will no longer stop on a plan too small to be metering our day, and a run that loads zero keys now refuses to start instead of quietly burning the free tier and poisoning that reading for everything else. Details in the table below. Restoring the key file is a Mac-side job and it needs you.

Q2Is the video-graph lane still switched off?

Yes, for the whole cycle, all 30 of its runs, on the same $50 lifetime spending cap as yesterday. Every one of those runs printed the same line and quit in about two seconds. It produced nothing today, against 8 good leads yesterday and 45 the day before.

Nothing new is wrong with it. Yesterday's fix made the stop message honest, and it now says plainly that the cap is lifetime, that waiting does not release it, and what the lane costs. 1,933 seeds are still unwalked, at 2.7¢ per good lead, which is the cheapest in the pipeline.

One reporting note worth knowing. The automated snapshot lists this lane's reason for sitting idle as the quota pause from Q1. That is wrong: the lane's own logs say the cost cap, on every run, including runs from before the key file emptied. The quota pause is real for the other lanes and not for this one.

This is a spending decision and it has been waiting two days. One environment variable and a service start brings it back.

Q3Take the outage out. Was the rest of the day any good?

No, and the reason is the one carried from yesterday: the main lane is deep into a book it has already walked six times. The recommended-videos feed walked 10,346 seeds today, more than any day this week, and got 64 good leads for them.

That is a mid-lap reading and yesterday's debrief established why those flatter or steepen before the lap closes, so treat it as a direction, not a rate. The direction is down. Lap 6 closed at 0.014 good leads per seed. Lap 7 is running at 0.006, and it has 855 seeds left, so it will close within hours of the keys coming back. Lap 1 ran at 0.45.

The keyword lane tells the same story from a different angle. It ran 716 finder passes and 715 of them faded, meaning almost every pass came back under the threshold that says a pass was worth running. It got 31 good leads across all 716. Every session opened short on terms, and the term-starvation reading fired 23 times.

So both of the lanes that were actually running are scraping. That is not a fault to fix, it is the supply question in the recommendations: every lane is now fed only by leads the pipeline itself found, so when yield falls, so does the seed supply, and each lap is worse than the last.
