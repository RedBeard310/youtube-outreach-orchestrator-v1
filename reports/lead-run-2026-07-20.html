The three questions

Q135/35 sessions hard-walled and the dashboard screamed finder_hard_wall — so why is +151 a good day?

Because the hard-wall is benign, and has been since the block began. Each session's finder mines the handful of probe terms discovery invented that pass, then aborts on No active terms to process — the autocomplete refuel that used to keep the active pool full is IP-blocked (see Q2). Two nonzero aborts trip the "hard wall," so all 35 sessions log one. But the finder keeps finding through the independent discovery lane, and the overlapped verify+promote lane keeps sweeping the pitchable pool into approved_hold regardless of whether this session's finder produced anything. That decoupling is why sessions with an instant exit-1 still parked 16, 19, 21, even 31 leads. The hourly check-in read all 35 walls correctly as benign term-supply and paged no fix-agent — $0 Claude spend (the 086affb no-page rule, holding).

Q2Day 4 of the autocomplete IP-block — what's still dead, and what's carrying the day?

Dead: the keyword-harvest refuel. Google/YouTube's public suggest endpoint has been IP-blocking this VPS with sustained HTTP 403 since 2026-07-17. When a harvest does run it collects raw tails but the ICP-prefilter keeps 0 / 853 (the 403-degraded suggestions are junk), so the reservoir stays empty — STOCK-UP on all 35 sessions. The remedy is infra (rotate the egress IP / add a proxy), not code.

Carrying the day: the second, independent term lane — the finder's LLM frontier discovery (discover-veins.ts), which invents probe: veins the finder mines in-session and is untouched by the blocked endpoint. It pivoted hard into Real Estate (159) + Health & Wellness clinics (61) = 75% of all pitchable — the same routing-around that carried 07-19. Verify still runs (on RapidAPI; the direct YouTube keys are all exhausted/blocked, 0 available) and held its rate: 294 pitchable → 151 verified & parked, +137 dead-email creators swept to needs_contact (now 3,469).

Q3So is +151/day sustainable — or are we quietly running down a reserve?

Holding, but not compounding — and today exposed a self-inflicted leak. The day's real find-volume is genuine (294 newly-discovered pitchable, dated today), so this isn't pure backlog drain. But two structural weaknesses cap it:

① The block-aware harvest guard was oscillating. The guard reads the 1–2 newest session logs for a 403 marker — but a session that correctly skips leaves a clean log, so after two skips the window holds no block evidence and the next session harvests again. Result: the harvest RAN 18× straight into a known-blocked endpoint this cycle (vs 45 correct skips), each run firing ~853 futile autocomplete requests and a wasted Haiku ICP-prefilter that keeps 0 — deepening the very block it's meant to dodge. Fixed today (see below).

② Discovery doesn't compound. evaluate-probes has promoted 0 winners for a 4th straight cycle — every invented vein converts below the promote bar, so the finder re-invents veins nightly instead of building a growing proven-term base. Combined with the 4-day-dead harvest, the durable term supply isn't growing; the LLM lane is doing all the work, fresh every day. Steady, but a countdown if the frontier lane ever fades.
