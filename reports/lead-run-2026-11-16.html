The three questions

Q1Why does a lane that is four days dead read as 1.6 hours quiet?

Because the fix that made it visible became one of the instruments that measure its silence.

lane_silent_hours is the age of the newest trace the lane leaves on disk, taken across every file it writes. Until 11-15 that was two files, both written only by a tick that reached the batch, so a lane refusing early left nothing behind and the number grew. That is how it reported 71.6 hours yesterday and sized the outage honestly.

Yesterday’s fix added a third file, apify-endspec-tick.json, written by every exit path including the refusal. The refusals happen hourly. So from the moment it deployed, the newest trace is never more than an hour old, whatever the lane is doing.

Fixes shipped this cycle

Both halves of one fix: a refusing lane can now be sized, instead of being measured by a silence it no longer has.

1. The tick stamp carries how long the same answer has run

youtube-email-outreach-v1, scripts/apify-endspec-loop.sh. tick_note() now reads the previous stamp before writing. An identical outcome and reason carries the start forward and counts up; anything different starts over. 

{"at":"2026-11-16T09:22:09Z","outcome":"skipped",
 "reason":"could not read the Apify monthly ledger",
 "since":"2026-11-12T10:20:12Z","consecutive":48}

One unbroken run of refusals is then one readable fact, rather than a stamp that always looks a few minutes old. Written through a temp file and os.replace, so a reader never sees a half-written stamp, and it still can never be a reason the tick fails.

Verified by running the function against a scratch copy of the live stamp: it carries forward from a pre-fix stamp that has no since (falling back to that stamp’s own at), increments across repeats, resets when the answer changes, and starts fresh from an unreadable prior file. bash -n clean. The auto-sync timer committed it under its own message (7b8f76e10) before the autopilot-improve: commit could land, so the change is on the branch and will push; the message is the timer’s.

2. Silence stopped measuring a dead lane

youtube-outreach-orchestrator-v1 a230365. A new exported apifyTickFacts() reads the stamp and publishes three fields beside the existing ones:

  • lane_last_tick_since — when the current answer began.
  • lane_last_tick_streak — how many consecutive ticks have given it.
  • lane_refusing_hours — how long an unbroken run of refusals has lasted at the cycle end. This is the field that sizes an outage now.

Anything but ran counts as a refusal, including an outcome this reader has never heard of, so a new exit path added to the loop script later cannot read as a healthy lane without an edit here. All three are null on a stamp written before today, which carries no since: unknown, and explicitly not a run that started this tick. Defaulting that to “started now” would publish the reassuring answer on exactly the lane this exists to catch.

lane_silent_hours stays, with its meaning narrowed in the block note: it now only answers “has this lane stopped running at all”, which is a different and rarer question. Verified against the live stamp before committing (it is the pre-fix shape, so it correctly reports unknown and will start carrying from the next tick) and against the shape the next tick will write. Typecheck clean, five new selftest assertions, all passing.
