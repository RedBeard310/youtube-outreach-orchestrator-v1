01The real bottleneck

"We ran out of keywords" is only partly true. Three facts reframe it:

  • Creators are not exhausted — easy query supply is. Each genuinely fresh term still yields ~0.9 pitchable creators. The drought is in net-new term ideas, because a freeform LLM brainstorm collapses back into its own priors.
  • The second constraint is email verification. Only ~40–54% of pitchable creators have an auto-verifiable email; ~2,600 score-≥6 creators already sit unreachable in needs_contact. Mechanisms that surface creators with findable business emails are worth extra.
  • Once generation is industrialized, the bottleneck moves. Every candidate term still costs a 100-unit YouTube search to validate — so after Track 1 ships, probe-testing throughput and verify-rate become the frontier again. That is what Track 3's graph/playlist mechanisms attack (1–2 API units for many channels instead of 100 per search).

02Track 1 — Industrialize keyword generation

Stop asking an LLM to imagine phrasings; mine them from data at scale.

Google Keyword Planner (Google Ads API) — worth applying, not worth waiting for

  • Access changed Oct 2025: new developer tokens land in an "Explorer" tier that blocks keyword planning; test accounts return dummy data. Real GenerateKeywordIdeas requires Basic Access — free, "keyword research" is now an accepted use case, but there is an acknowledged application backlog (Feb 2026): realistically 1–4+ weeks.
  • Capacity once approved: seeds of 20 keywords/request, URL seeding, whole-site seeding (up to 250K ideas/domain), 10K ideas per page, free. Seeding with ~50 proven winner terms + 20 winner business sites ≈ 20K–60K raw strings → ~1,500–6,000 net-new ICP-relevant probe terms per harvest, repeatable monthly.
  • Caveat: volumes are Google-search, not YouTube — acceptable, because we need idea breadth; the probe → promote/retire loop already measures actual YouTube yield.

The probe plumbing is already source-agnostic: evaluate-probes.ts promotes/retires anything with a probe: prefix, unmodified. New module src/discovery/external/ + one CLI: source adapters (autocomplete → DataForSEO → Ads API later) → normalize + dedupe against all 3,856 existing terms → cheap Haiku ICP-prefilter (~300 candidates/call, keeps consumer-generic sludge out) → reservoir file → drip 100–200 probes/day into the terms table as probe:kw:<date>. Drip-capping matters because each probe test costs a 100-unit search — 5K candidates is months of testing throughput.

03Track 2 — Expand the vertical universe

Not new phrasings within known niches — new universes of educational-video creators selling high-ticket services. The agent first read the full existing coverage (ICP file + both seed CSVs, 923 terms — much wider than the code suggests) so these are net-new.

The single biggest supply injection: Commonwealth geo-clones. The entire proven US core — solicitors, IFAs, chartered accountants, buyer's agents, SMSF/pension specialists — exists in the UK/AU/CA/NZ with less YouTube saturation and higher email findability (firm-heavy professions publish contact pages). One vocabulary map (attorney→solicitor, 401k→pension/superannuation, realtor→estate agent) multiplies everything already proven. Cheap to probe; check US-tuned host-finder/email-pattern assumptions and whether non-US clients are wanted before scaling.

04The repeatable vertical-discovery engine

So verticals never become another static list that exhausts in three weeks. Mirrors the term-level promote/retire loop the system already trusts — one level up.

PieceWhat it does
1 · Verticals become data, not codeMove FRONTIER_VERTICALS into an Airtable verticals table with lifecycle state (candidate → probing → proven → saturated → retired), source, and rollup stats. Saturation becomes a measured fact, not a vibe.
2 · Taxonomy-walker generatorThe anti-exhaustion trick: instead of freeform LLM brainstorming (which reconverges on its priors — the root cause of today's drought), walk an external, exhaustive, checked-in taxonomy — ~1,000 six-digit NAICS service leaves + licensed-professions lists — with a stored cursor, one branch per fade event, scoring each candidate 1–5 on the four ICP criteria. Years of supply at fade-rate.
3 · Free demand validationBefore a candidate vertical costs a 100-unit search, template "how to get clients for X" / "how to grow a X" into the free autocomplete endpoint. Hits = humans search it = creators serve it → spawn 3–5 probe terms. Zero hits → retire with reason, one API-free call.
4 · Geography as a multiplier axisRegistry is vertical × geo. A one-time vocabulary map lets every proven US vertical spawn UK/AU/CA/NZ clones as candidates automatically — the largest single supply injection available.
5 · Close the loopevaluate-probes.ts already promotes/retires terms; add a vertical rollup: first N probes all die → vertical retired; any probe hits qr≥10% → vertical proven, unlocking full term generation. All decisions log to discovery-decisions.jsonl.

05Track 3 — Non-keyword mechanisms, ranked

The one insight under all eight. The keywords aren't exhausted — the search is. Every term costs a 100-unit YouTube /search (the one scarce bucket); these mechanisms spend 1–2 units for many channels by walking the ~3,000–4,000 confirmed score≥6 creators we already own instead of searching for new ones. They run when the search bucket is exhausted, so they're complementary to the keyword tracks, not competing for the same quota. Several arrive with a business website attached — so they attack the email-verify constraint at the same time as supply.

Probe status (honest). The workflow ran to completion — grounding → 6 ideation lenses → portfolio ranking, all 20 agents, 0 errors. An earlier revision of this page said the final probe pass was "truncated to control cost". That was wrong — the run had not stalled, and the claim is corrected here. Several mechanisms were partially live-validated during ideation (flagged inline below), and every card carries a self-contained, read-only probe (≤6 API units) to confirm it before any build.

1

Seed-graph neighbourhood walker MEASURED 2026-07-16 — premise falsified, descoped

As proposed: one graph-walking suite over our confirmed seeds, three edge types sharing one sink: watch-next lookalikes (free RSS + free watch-page HTML — zero quota), featured shelves (channelSections.list, 1 unit/seed — owner-endorsed sister channels, highest precision), and playlist co-curation (2–3 units). A persistent frontier scheduler would prioritise seeds by firm-likeness × new-per-unit and auto-enqueue every net-new winner as a fresh seed, turning a backlog sweep into a self-refeeding daily source.

What a 20-modal-seed live gate actually found:

  • Net-new rate 83.8% (196/234) — confirmed. The graph genuinely reaches channels all 3,856 terms never surfaced. This is the mechanism's real asset.
  • ICP precision 10.0% (4/40; 14.8% of the 27 that scored) — the hypothesis failed. The whole 2–3 day design rested on modal 5k–200k firm seeds hitting 20–30% vs. the 10–17% the first probe got from 19M-sub edutainment megas. They hit 10.0% — statistically indistinguishable. Seed size does not drive precision. Yield: ~0.6 net-new score-≥6 per seed, not 30–80/day.
  • The featured-shelf edge is dead on modal seeds — 0 results on 16 of 17. The highest-precision, API-legitimate edge only fires on large channels, whose neighbourhoods are exactly the contaminated ones. The mechanism therefore rests entirely on the free but ToS-gray, brittle watch-page scrape.

Descoped, not killed. The frontier scheduler is cut — prioritisation only pays if seeds differ in quality, and precision was flat across the band; compounding is cut too, since at 10% density re-seeding regresses toward the consumer cluster. What survives is a dumb one-time backlog sweep of the frozen seed list, which still pays for itself on bucket economics alone: it spends the abundant requests bucket (~221k idle) and zero search (~5k — the one the entire term engine competes for), at roughly 5–7× the leads-per-unit of a 100-unit search.

Revised: ~0.6 net-new score-≥6/seed, one-time · /search quota: 0 · Build: ~½ day (scripts/graph-sweep.ts) · reuses the existing dedupe→Haiku-score→Airtable sink
2

Guest-edge miner partially validated

Two free transports into one guest-edge module. In-YouTube: harvest /@handle and /channel/UC links from interview-format seeds' video descriptions (extractor already exists). Off-YouTube: free no-key iTunes Search API → podcast RSS → episode show-notes → guest firm site → grep for a YouTube link; the podcast hosts are direct ICP too. Attacks both constraints — guests are owner-operators the seed pre-vetted (often never rank in search) and arrive with a known business website, so verify plausibly 70%+ vs the 40–54% baseline. Live check: "Profit with Law" show-notes yielded firm sites + Calendly links; lawfirmmentor.net → @LawFirmMentor.

Yield: 20–45/day · quota: ~2–3 units/day · months of depth (dozens of podcasts × 72 verticals)
3

Association-directory sweep partially validated

Member directories are public marketing vehicles — un-defended and ICP-by-construction: NAPFA / XYPN / FeeOnlyNetwork (fee-only advisors), AmSpa (med spas), state bars, AICPA, ICF (coaches). Each profile carries a firm-website URL → fetch homepage/footer/about → grep for a YouTube link → batch-validate 50 ids per unit. Completely uncorrelated with 3,856 terms of search coverage, so its net-new rate should be the portfolio's highest, and the firm site is known before triage → best verify-rate of the set. Live check: NAPFA find-an-advisor returns HTTP 200; aggregators like Justia 403 (skip them).

Yield: firm-heavy, high verify · /search quota: 0 · new src/sources/directory-sweep.ts + per-directory adapters
4

Autonomous recursive autocomplete miner partially validated

Generalise mine-autocomplete.ts into the campaign fade-hook: programmatic seeds (top terms × proven shapes × promoted verticals) → 2-level a–z recursion → hundreds of strings at zero YouTube quota → one Haiku ICP-classify as prefilter → survivors written as probes via the existing discover-veins path. The fastest fix for the stated problem (term exhaustion), demand-verified by construction (real typed queries), already proven across three manual rounds. Live check: "cost segregation" → 10 tails; a med-spa seed enumerated sibling professions (photographer/designer/PT) for free.

Yield: 20–40/day → 10–20 steady · quota: 0 · Build: ~1 day (harvest + probe-writer both exist)
5

Shape × vertical × geo combinatorial engine

Deterministic cross-product — no LLM imagination: 7 proven shape templates × the full vertical taxonomy × a geo axis for firm-heavy niches ("estate planning attorney texas"). Free autocomplete-existence prefilter keeps only demand-proven combos; a coverage bitmap means the campaign always knows which cells are un-mined, so it structurally cannot reconverge the way the discovery LLM does. The geo axis activates the dormant geo_scope field and is the strongest verify-rate raiser (local firms = contact pages, expect 60–75%). One cell already live: "cost segregation" returned 10 demand-verified tails.

Yield: 25–45/day for 3–4 weeks · quota: 0 to generate · watch-out: give the local cohort its own promote threshold (local channels skew small)
6

Winner-corpus vocabulary miner partially validated

Mine the two zero-quota corpora of confirmed-ICP language we already own but never read: video titles (free RSS, ~15/channel × ~4,000 channels → n-gram cross-channel frequency filter — a phrase used by 3+ independent winners is peer vocabulary) and self-descriptions (about_description already in Airtable → batch-LLM-extract named services like "cost segregation study", audiences like "for dentists"). The most ICP-grounded corpus that can exist, and it turns the 2,600-lead needs_contact pile into a discovery asset before the recovery engine is built. Live check: RSS title format confirmed; cross-channel frequency filter is the load-bearing part to watch.

One-time vein: 300–800 net-new terms + 100–300 verticals (which multiply #4 and #5) · quota: 0 · a few $ of LLM
7

Semantic-dedupe + shape-learning refinery multiplier, not a source

The layer that makes the other six affordable. (1) Semantic dedupe: replace the exact-lowercase avoid-set with stem-normalisation ("…for law firms" vs "…for a law firm" both burn a 100-unit search today) so near-dupes are rejected before they cost quota — every probe writer routes through it. (2) Shape learning: today's fixed regexes bin every novel framing into "other" so a winning new shape can never be amplified; persist an LLM-assigned shape label + a per-shape verify-rate column, giving discovery its first feedback signal toward email-findable framings.

Build: 1–2 days · saves /search quota forever (+5–10 net-new/day reclaimed, scaling with throughput)
8

Comment-author peer miner lowest confidence — diversity pick

commentThreads.list on high-view winner videos returns up to 100 author channel-ids free; peers self-identify in B2B comments ("as a fellow estate attorney…"). The economics trick: batch 50 author-ids into one channels.list unit and prefilter before any full triage. The only mechanism that surfaces young practitioner channels before they can rank in search — net-new by construction — and the comment text is a warm personalisation hook for the future recovery engine. Hard rule from the live probe: run only on ≥10k-view videos (a small winner's video had 0 comments).

Yield: 5–15/day · cheapest cost-per-candidate-screened · kill fast if author-resolution is low
