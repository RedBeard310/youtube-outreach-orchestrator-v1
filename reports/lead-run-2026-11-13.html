orchestrator		 A mailbox sliding from watch to stop stops being charged against the clear band. band_moved_to_normal, band_moved_to_watch and band_moved_to_stop are arrivals, how many mailboxes the gate handed each band, and the subtraction the 11-09 fix installed assumes every arrival in watch or stop came out of normal. One did not, today, and the identity went short by exactly one. That matters because of what the reader is left to conclude: the only documented shape that breaks the subtraction is the 11-10 short read, and band_moves_comparable truthfully reported that as absent. A clean day read as an untrustworthy instrument. band_left_normal is now the arrivals in watch or stop whose band immediately before the move really was normal, so band_normal_prev plus the returners minus band_left_normal closes by construction. A run names the mailboxes it moved and never the band it moved them from, so the prior band is reconstructed by walking every retained run in order, including the ones behind the window, and a mailbox no run can place falls back on that run's own band deltas: a run with no returners whose clear count fell by exactly the number of demotions took all of them out of normal, and one whose clear count did not move took none. Anything else stays in band_left_normal_unknown, which makes the figure a lower bound rather than a guess. Verified: typecheck clean, 365 selftest assertions with 5 new ones over the real 11-12/11-13 gate history, including a run that promoted and demoted at the same time and therefore must refuse to settle. Run against the live gate state it returns 2 departures, 0 unknown, and 44 + 2 − 2 = 44 exactly.
