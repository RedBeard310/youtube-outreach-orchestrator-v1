The three questions

Q1Why did fresh finding flatline to zero?

A term-supply refuel deadlock — both independent sources are dead at once. (1) The finder's only cheap term-refuel, the public autocomplete/suggest endpoint, has been IP-blocked since 2026-07-17 (sustained HTTP 403 — an egress-IP block, not term exhaustion). The one harvest that squeezed through this cycle got 808 candidates before the circuit-breaker tripped at 8/42 seeds — and the ICP-prefilter kept 1 of 808. (2) The LLM frontier-discovery lane that carried days 2–5 saturated on 07-21: every generation now dedupes to ~0 net-new against a static term table.

Yesterday's durable fix — FRONTIER_VERTICALS +19 — was supposed to give discovery fresh ground. It didn't convert: the table moved only 6,983 → 6,998 and discovery stayed dry-locked all cycle (went dry at 6998 terms … no new ground). With no new terms entering the table, the finder mines a 0–1-term saturated pool, aborts No active terms, and hits its two-strikes hard wall on 43 of 43 sessions.

Q2Then why did +52 still land in approved_hold?

Because parking is downstream of verifying, not finding. The verify/promote lane is independent of the finder: each session pulls a handful of already-found-but-unverified leads from the standing pool, verifies them, and promotes the passers (5, 6, 3… per session) → approved_hold, while auto-sweeping dead-email score-≥6 leads → needs_contact (now 3,605).

So the metrics feed's 619 discovered · 119 pitchable is mostly status churn — verify promotes, needs_contact sweeps, re-scores of the standing backlog — not net-new channels. The honest net-new-finding number is the finder's own counter: 1. The backlog is a finite reservoir; two more days like this and the +52 line falls too.

Q3Why hasn't it self-healed — and is it safe to leave running?

The remedy is infra, and the code workarounds are now exhausted. Unblocking the endpoint means rotating the VPS egress IP / adding a proxy — no code path and no fix-agent can do that, and secrets are operator-only. Every cheap code lever has now been spent across the last five debriefs (circuit-breaker, block-aware harvest, block-backoff, discovery dry-guard, +19 verticals) and each bought less; the frontier lane was the last one, and it saturated.

Compounding it: 0 working direct YouTube keys and RapidAPI at 98.9% of cap all cycle — so even a term refuel couldn't be mined right now. Two infra axes are pinned at once. It is safe to leave running: $0 Claude spend, clean ~30-min rests (no thrash), backlog still draining, nothing money-path or auth-critical at risk. The loop was left up for the next cycle — correctly. But growth is now entirely backlog + needs_contact, and both are stopgaps.
