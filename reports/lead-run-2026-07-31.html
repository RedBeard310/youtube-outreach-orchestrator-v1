The one real inefficiency I found — the finder re-probing a genuinely quota-exhausted direct key on each fresh pass — was left alone deliberately: a quotaExceeded request is not billed by YouTube (you can't exceed the cap you've already hit), so the only cost is ~16 wasted round-trips/day at zero quota. The current per-process stickiness is the documented-intended design. No code shipped this cycle.
