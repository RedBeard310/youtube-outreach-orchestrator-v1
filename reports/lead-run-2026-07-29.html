Self-improvement shipped this cycle

Rotate the keyword-harvest seed offset so blocked re-probes mine fresh slices

finder 04b88fa · scripts/keyword-harvest.ts · verified: project typecheck clean + runtime simulation (6 blocked re-probes → 42/42 seeds covered, zero drift when unblocked)

Under the persistent block the circuit breaker aborts the harvest at the same seed every 6h, so the identical front seeds get re-mined while everything behind the block point sits untouched. The fix persists a start-offset (logs/keyword-harvest/.seed-rotation.json) and walks it forward by the seeds actually harvested each run, so consecutive block-truncated re-probes cover the whole list across a few runs instead of re-storming the same head. It's a no-op when unblocked (a full 42-seed harvest advances a full lap and wraps to the same start) and best-effort (a missing/corrupt state file just means offset 0 — never blocks the harvest). This is aligned with the 07-24 finding — the leak extracts real terms; don't gate it, make it reach more ground — and it's self-clearing: when the egress IP rotates, the normal full cadence resumes untouched.

Honest scope: the high-confidence win is efficiency + reach (stop re-mining 8 saturated seeds, spread the leak across all 42, ease pressure on the rate-limit). Whether the 34 unreached verticals still hold keepable ICP terms is uncertain — but they're the only untried ground an autonomous refill can come from, and this is what lets the machine try them.
